# Endpoint and long-request investigation

Observed failure: both initial affine proposer HTTP requests exceeded the frozen 300-second client timeout. Both used a complete role prompt and max_tokens=4096, temperature=0, stream=false. The server remained alive/busy. There was no completed response available for those calls, so actual generated token count and the precise cause of their delay are unknown.

Boundary evidence: exact outgoing requests were saved; timeout exceptions were recorded; Lemonade health identified the loaded Qwen/FLM/NPU/context 70728. Two subsequent review calls returned HTTP 200 at 94.99 and 126.90 seconds. Their reported completion counts were 241 and 239 and decoding speeds 8.38/8.31 tokens per second. One final content was a complete envelope; the other omitted the closing object brace despite finish_reason stop. No coordinator corrected it.

Working examples: a tiny direct prompt returned READY; another returned valid JSON; a concurrent tiny pair returned both expected labels. These establish basic transport/inference and JSON output for trivial requests at the same context. They do not establish a root cause for the long-request delays. Their pair timings are consistent with serialization/queuing; we did not inspect the backend scheduler.

Hypothesis for the next controlled operational intervention: lowering the requested output ceiling from 4096 to 512 may reduce exposure to long decoding/queued execution and make the twelve-slot run complete within its timeout. At the observed decoding rate, 4096 tokens alone exceed 300 seconds; 512 tokens would need about 64 seconds, before prefill/queuing/overhead. This estimate is not a guarantee and does not prove the original requests used their whole allowance. Only the output ceiling changes. The run remains exploratory, with truncation and schema attrition reported honestly. If it does not work, do not claim the endpoint is broken or the budget hypothesis confirmed.

No Lemonade context/backend setting has been changed by the coordinator. No response repair, retry or hidden answer feedback is used. Frozen original sources and unfinished-call evidence remain available in runs/local-qwen1.
