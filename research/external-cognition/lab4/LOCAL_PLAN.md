# Local Qwen run plan

This adapter is a bounded, offline-testable runner for the preregistered Lab 4 local replication. It sends no request during preparation. It never downloads, loads, unloads, or reconfigures a model. The frozen target comes from `LOCAL_RUNTIME_DISCOVERY.json`: Lemonade on loopback, qwen3.5-9b-FLM / checkpoint `qwen3.5:9b`, FLM on NPU, and the observed configured context. Before any inference, a fresh read-only health/model preflight must match the frozen version, loaded model, checkpoint, recipe, device, ready status, and context.

The schedule is the pilot's fixed twelve slots over seeds 4201 and 4202: paired proposers, paired cross-reviewers, then paired shared/raw integrators per seed. Each request is a fresh one-user-message chat completion with a manifest-frozen `max_tokens` value from 1 through 4096 (default 4096), `temperature=0`, and `stream=false`; no response-format option is sent. A lower cap such as 512 requires a separate output directory and preregistration snapshot. Pairs are dispatched with two workers. A local backend may serialize them, so concurrency in the coordinator is not a claim of concurrent hardware inference.

Every dispatch consumes its scheduled slot, including timeout, HTTP error, incomplete body, wrong returned model, malformed content, and rejected protocol response. The runner makes no retries. It saves exact outgoing request bytes before dispatch and the full returned HTTP body before decoding. Extracted `message.content` is preserved byte-for-byte as UTF-8 without markdown stripping, repair, or reasoning substitution. `reasoning_content` is stored separately and is never included in another prompt. Usage, finish reason, response model, timestamps, and hashes are recorded when available; `finish_reason=length` is marked potentially truncated while retaining the content unchanged.

Only loopback HTTP is permitted. Redirects are disabled; only the health, models, and chat-completion paths are allowed. A preparation manifest hash and endpoint binding are checked before preflight and dispatch. A readiness mismatch writes a zero-slot receipt and can be retried explicitly after the server is corrected. Once any run has started dispatching, the run directory cannot be resumed or automatically rerun. A crash can therefore leave unattempted slots; these remain distinct from recorded failures. The offline evaluator runs only after all twelve pilot slots have an outcome.

The local feasibility question and outcome definitions are in `LOCAL_PREREGISTRATION.md`. This runner is a local replication, not a native-vs-local causal comparison.
