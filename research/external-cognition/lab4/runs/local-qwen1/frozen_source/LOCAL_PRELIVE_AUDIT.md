# Local runner pre-live audit

Date: 2026-10-01. Independent source and fake-transport audit of `local_runner.py` against `LOCAL_PREREGISTRATION.md` and `LOCAL_RUNTIME_DISCOVERY.json`. No live inference calls were made.

## Clearance

The runner is eligible for the preregistered local run after the source freeze already in place. The initial review found four blockers: urllib redirect following, no runtime manifest/endpoint integrity check, rejection of the known checkpoint alias in response metadata, and two stale expectations in the initial fake-transport tests. The implementation now disables redirects and retains redirect responses as failures, verifies the manifest hash and exact loopback chat endpoint before any HTTP request, accepts only the two frozen model identifiers (`qwen3.5-9b-FLM` and `qwen3.5:9b`) while recording the returned identifier, and has aligned tests. Prompt-byte hashes are checked against their recorded/frozen values before dispatch; source and pilot run input hashes are checked before execution.

The reviewed paths use only loopback HTTP GETs for health/model readiness and POSTs to `/api/v1/chat/completions`. Readiness checks the already-loaded model, checkpoint, FLM recipe, NPU device, ready/backend-alive state, Lemonade version, and configured context against the frozen discovery. No model-management endpoint, download, or reconfiguration path is present. Each completion request contains one user message, `temperature: 0`, `max_tokens: 4096`, and `stream: false`; response-format enforcement is omitted. Calls are dispatched as six concurrent pairs across the two seeds. There is no retry path; `run_started.json` prevents an attempted run from being replayed, while a readiness failure consumes zero model-call slots and can be retried explicitly.

The outgoing request bytes are saved before dispatch. Full HTTP response bytes and response metadata are saved before parsing or content extraction. Final message content is persisted as returned without trimming, Markdown removal, or JSON repair; reasoning content is saved separately and is not passed to another role. HTTP errors and incomplete response bodies consume their one scheduled slot and retain their available response bytes and failure evidence. The runner submits all twelve recorded outcomes before invoking the offline pilot evaluator. Shared and raw integrators receive separate fresh prompts; only the shared integrator receives the state projection, and the coordinator does not select a claim or candidate.

Verification: `python -m unittest discover -s tests -q` completed successfully (31 tests, 9.726 seconds). Added runner regressions cover manifest endpoint tampering, exact returned-model aliases, redirect prevention, partial HTTP responses, request artifact preservation, concurrent pairs, twelve-slot bounds, readiness gating, and rerun prevention. This audit establishes protocol/runner controls only; it does not assert model correctness, performance, physical parallel execution by the backend, or any universal reasoning capability.
