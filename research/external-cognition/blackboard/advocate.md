# Advocate case: externalized cognition and incremental reasoning

Date: 2026-10-01

## Strongest qualified case

The defensible version of the hypothesis is not that a notebook makes an incapable model universally capable, nor that persisted text is itself reasoning. It is that a solver can distribute a task across (a) a model that proposes/revises operations, (b) an external representation that preserves task-relevant intermediate state, and (c) an execution or validation process that updates that representation. If the next model call is conditioned on the prior state and its validated transition, it may advance a computation whose complete evolving state is cumbersome or impossible for that call to retain internally. Human problem solving and LLM scratchpad/tool studies establish credible mechanisms and narrow empirical precedents. They do not yet show the target claim under matched compute and measured model capacity.

### Operational definitions

- **External state**: an inspectable, durable representation outside model activations/context (e.g., a table, symbolic board, program variables, proof ledger) containing task-specific intermediate variables, relations, commitments, and provenance. A factual corpus that only retrieves answers is external memory, not sufficient evidence of reasoning state.
- **Reasoning transition**: a state-changing operation that follows from the problem plus current state (e.g., derive variable value, update board, discharge a subgoal, eliminate a branch). It must be specified as input state -> proposed operation -> validated output state, with invariants and an audit trail. Retrieval alone is not a transition.
- **Coherent advancement**: each accepted state obeys task rules, preserves prior valid constraints, tracks unresolved/contradictory items explicitly, and supports a correct next step after context reset. End-answer correctness alone is insufficient; transition correctness and state invariants should be scored.
- **Internal capacity limit**: a pre-registered, empirically measured limit for a particular model/configuration/task family (e.g., accuracy collapses above a working-state size when the task is supplied in a single uninterrupted call, across matched controls). A context-window limit alone or artificial prompt clipping is not proof of native representational inability.
- **Externalized reasoning vs external memory**: memory makes an already established fact available again; externalized reasoning makes the evolving intermediate state actionable so later operations can continue a derivation/search. Systems can combine both, and the evaluation must separate them.

### Evidence that favors the mechanism

1. Human cognition includes useful operations on the world, not only internal recall. Kirsh & Maglio distinguish epistemic actions (actions that reveal information otherwise hard to compute mentally) from pragmatic actions, using data and examples from Tetris. Laland et al. (2019) studied active environmental manipulation in Raven matrices and found that environment-altering actions were clustered between periods of apparent inactivity, consistent with alternating internal and external operations. The later task paper's measured behavior supports a perception-action loop, not a claim about model internals.
2. Scratchpad work demonstrates that explicit intermediate state can change what a fixed model can compute. Nye et al. train Transformers to emit intermediate computation steps and report substantial gains on tasks from long addition to arbitrary-program execution. This is stronger than a notebook-as-archive result: intermediate results are fed into continued generation and guide subsequent computation. But the learned scratchpad is in the generated token stream, and the experiment adds sequential token computation; it is not an independent store versus a compute-matched no-store baseline.
3. Program-of-Thoughts (PoT) explicitly assigns reasoning expression to the language model and numeric execution to a Python interpreter. Across five math-word-problem and three financial-QA datasets, authors report around 12% average gain over chain-of-thought across their evaluated settings. This establishes that a model may formulate a transition in executable form, external machinery calculate a state value, and the model continue from that result. It is narrow to numerical tasks, relies on executable code and task answer computation, and confounds external representation with exact arithmetic/tool capability.
4. Tree of Thoughts (ToT) represents candidate reasoning as coherent units, branches among alternative states, self-evaluates, and can look ahead/backtrack. NeurIPS paper reports improvement on three planning/search tasks; e.g., Game of 24 GPT-4 success rises from 4% with CoT to 74% with ToT in that study. This is evidence that explicit branching/state management can aid inference, not that the state is persistently advanced by a weaker model. The design also invokes many model calls/tokens and search, so extra inference compute is a strong alternative explanation.
5. DaSLaM (EMNLP 2023) separates problem decomposition from solving, with a small fine-tuned decomposition generator coordinating larger-model solvers. The authors argue and demonstrate that these capabilities can be modularized, avoiding a monolithic call's simultaneous decomposition-and-solution burden. It is relevant to decomposition and distributed roles but does not directly evaluate durable external state or same-model inability.
6. CoT empirical work shows that relevance and correct ordering of steps matter, but invalid demonstrations can retain 80–90% of correct-CoT performance under reported measures. This is a caution for interpreting readable traces as faithful causal reasoning: a fluent external trace may be scaffolding/format cue, not a transparent account of the computation. It nevertheless establishes that ordered intermediate rationale presentation can act as a useful prompt interface.

### Technical-practice corroboration (low evidential weight)

An April 27, 2026 Hugging Face forum thread includes practitioner recommendations to treat the runtime as memory owner, store durable state externally, and compose a small active context for each call; another participant reports physical prompt/response files as reference points. This is useful as evidence that developers distinguish runtime-owned state from a prompt working view, and it surfaces audit/erasure concerns. It is an anecdotal discussion, not controlled evidence, and does not establish improved reasoning.

### Limits and countercase to acknowledge

- None of the cited sources jointly establishes: measured failure to internally maintain a particular representation; answer-free external state; isolated, incremental transition benefit; context reset/fresh solver; matched token/model-call/tool compute; and performance specifically above the model's native capacity threshold.
- Scratchpads, CoT, and ToT add generated tokens or calls. PoT adds deterministic arithmetic. Improvements could be explained by extra inference-time compute, exact tools, prompt structure, or search rather than externalization as such.
- A static summary or RAG result can improve recall while silently omitting dependencies, confusing versions, or importing the answer. State mutation can also compound a bad transition. Correctness requires explicit invariants, provenance, and independent validation.
- Human cognitive findings are analogy/mechanism evidence, not evidence that a transformer has the same limits or benefits.
- The word “coherently” must be measured at each state transition. Correct final answers from self-consistency/branch selection do not show every carried-forward state was sound.

### Falsifiable prediction

On randomly generated state-transition tasks (e.g., long constraint-satisfaction, arithmetic dependency graphs, or symbolic planning) where answers are never stored and each item has a machine-checkable transition invariant, an external-state condition should outperform a stateless condition after forced context reset **only** above a preregistered internal-capacity threshold, while total model tokens, model calls, wall-clock/tool budget, and answer-bearing information are matched. Score transition validity and final solution separately. A useful specific prediction: with state in a canonical structured ledger, successive fresh calls should preserve more correct invariants and reach more valid terminal states than calls receiving only the original problem and equal-token generic context. If the advantage vanishes with matched budget, occurs equally below the threshold, or is fully explained by putting more task information in the state, the specific capacity-extension hypothesis is weakened or falsified.

## Dated debate record

2026-10-01 — Skeptic's strongest challenge: generic external memory or Turing-universal computation does not show that external state enables useful reasoning beyond a model's own representational limit. Scratchpads may merely add tokens; tools add compute or answer-bearing content; an agent can fail to read or correctly update stored material. Suggested decisive test: withhold answer-bearing information from the store, use random generated tasks, compare staged external state with a token/compute-matched stateless baseline, and require a gain specifically above a pre-registered internal capacity measure. I accept this as the main evidential gap and have incorporated it as the falsifier.
